# VIP_Pet

Питомец, который следует за VIP-игроком: ходит или парит рядом, бежит, когда игрок движется, стоит, когда игрок стоит, проигрывает анимации появления и смерти. Игрок целиком настраивает питомца в меню `!vip` (см. «Меню игрока»).

Порт модуля `Pet` из [ByDexterTR/CS2Plugins](https://github.com/ByDexterTR/CS2Plugins/blob/main/VIPCore/modules/Pet.cs) под API этого ядра (`VipFeatureBase`, `vipcore:core`).

## Установка

1. Соберите модуль вместе с остальными (CI кладёт его в `VIP_Modules.zip`) или вручную:
   ```bash
   dotnet publish VIPCore/modules/VIP_Pet/VIP_Pet.csproj -c Release
   ```
2. Скопируйте папку `VIP_Pet` в `addons/counterstrikesharp/plugins/` (рядом с `VIPCore`).
3. Загрузите модели питомцев (`.vmdl` / `.vmdl_c`) на сервер и клиентам (Workshop-аддон или FastDL — зависит от вашей схемы раздачи ресурсов).
4. Добавьте фичу `Pet` в нужные группы `vip.json` (см. ниже) и перезапустите сервер или смените карту. `css_vip_reload` подхватит новые записи, но **модели предзагружаются при старте карты**, поэтому новая модель заработает только после смены карты.

Строки меню берутся из `lang/*.json` ядра (ключи `Pet` и `pet.*`). Обновите `lang` ядра до версии с этим модулем, иначе пункты меню будут показаны ключами.

## Конфиг (`vip.json`)

Значение фичи — список питомцев:

```json
{
  "Groups": {
    "VIP1": {
      "Values": {
        "Pet": [
          {
            "name": "Cat",
            "model": "models/myaddon/pets/cat.vmdl",
            "speed": 260,
            "distance": 55,
            "animations": { "idle": "idle", "run": "run" }
          }
        ]
      }
    },
    "VIP2": {
      "Values": {
        "Pet": [
          {
            "name": "Cat",
            "model": "models/myaddon/pets/cat.vmdl",
            "animations": { "idle": "idle", "run": "run", "spawn": "spawn", "death": "death" }
          },
          {
            "name": "Drone",
            "model": "models/myaddon/pets/drone.vmdl",
            "flying": true,
            "height": 60,
            "scale": 1.2,
            "yaw": 90,
            "team": "ct"
          }
        ]
      }
    }
  }
}
```

Пути в примере — условные: подставьте модели и названия анимаций, которые реально есть на сервере или в вашем аддоне. Разные группы могут иметь разные наборы питомцев.

Имена полей — строго в нижнем регистре.

| Поле | По умолчанию | Описание |
|------|--------------|----------|
| `name` | — | название в меню (обязательно, служит и идентификатором выбора — не меняйте его у уже выданных питомцев, иначе сохранённый выбор игроков сбросится на первого питомца группы) |
| `model` | — | путь к модели `.vmdl` (обязательно) |
| `flying` | `false` | питомец парит над землёй и покачивается, а не идёт по полу |
| `speed` | `260` | скорость питомца; если игрок бежит быстрее, питомец ускоряется до его скорости ×1.1 |
| `distance` | `55` | на каком расстоянии питомец держится от игрока (значение по умолчанию — игрок может изменить в меню) |
| `height` | `45` | высота парения для `flying` (значение по умолчанию — игрок может изменить в меню) |
| `scale` | `1` | масштаб модели (игрок умножает его в меню) |
| `yaw` | `0` | поворот модели вокруг вертикали (°), если модель «смотрит» не туда, куда движется |
| `team` | `""` | `"t"`, `"ct"` или пусто (обе команды); питомец с чужой командой не показывается в меню и не создаётся |
| `animations` | пусто | названия анимаций модели: `idle`, `run`, `spawn` (играется при появлении в начале раунда), `death` (при смерти владельца). Пустая строка — анимация не меняется |

Запись без `name` или без `model` игнорируется. Все файлы из `model` всех групп автоматически добавляются в предзагрузку карты (читаются прямо из `vip.json`).

## Меню игрока

Пункт `Pet` в `!vip` открывает меню:

| Пункт | Что делает |
|-------|------------|
| Питомец: имя | открывает список питомцев группы + «Выключить»; выбранный питомец сразу появляется рядом с живым игроком |
| Размер питомца: xN | по клику переключает 0.5 → 0.75 → 1 → 1.25 → 1.5 → 2 → 3 (множитель к `scale` из конфига) |
| Дистанция следования: N | по клику переключает 30 → 45 → 55 → 80 → 120 → 200 → 300 |
| Высота полёта: N | только для летающих питомцев; по клику переключает 0 → 20 → 45 → 70 → 100 → 150 |
| Вижу своего: Да/Нет | показывать ли питомца самому себе (удобно, если он закрывает обзор) |
| Моего питомца видят: Все/Союзники/Только я | кому передаётся ваш питомец |
| Чужие питомцы: Показывать/Только союзники/Скрыть | чьих питомцев видите вы (доступно и при выключенном своём) |
| Сбросить настройки | возвращает размер, дистанцию, высоту из конфига и все параметры видимости по умолчанию |

Без сохранённого выбора VIP получает первого питомца своей группы. Все настройки хранятся одной записью в cookie ядра и сохраняются между сессиями; пункты настройки своего питомца скрыты, пока он выключен.

## Поведение

- Питомец создаётся при спавне игрока, исчезает через ~1.2 с после его смерти (успевает отыграть `death`), удаляется при смене команды, выходе игрока и выгрузке модуля.
- Если сущность питомца пропала (например, при рестарте раунда), он автоматически создаётся заново, пока владелец жив.
- Питомец не имеет коллизии и не мешает игрокам. При телепорте владельца или слишком большом расстоянии питомец мгновенно догоняет его.
- Питомцы не создаются для ботов.

## Отличия от оригинала

- Фича регистрируется как `Selectable` в `VipFeatureBase`: игрок включает и выключает её в `!vip`, а конфиг лежит в `vip.json` (в оригинале — отдельный модуль на `VipModule` с `GroupValue`). Поле `required` оригинала не поддерживается — для разных наборов используйте группы.
- Выбор питомца хранится в cookie ядра вместо `CategorySetting` оригинала; добавлены настройки размера, дистанции, высоты и видимости (свой питомец, кто видит мой, чьих чужих вижу).
- Скрытие питомца от других игроков сделано через `Listeners.CheckTransmit` API CounterStrikeSharp, а не через общий `EffectHide` оригинального ядра.
- Позиция и скорость владельца читаются напрямую из пешки через API CounterStrikeSharp, без вспомогательного `PlayerCache` оригинального ядра.
